# OGNL / Painless 表达式生成 Skill · PRD

> 本 PRD 由 `CONTEXT.md` 术语/边界 + `docs/adr/0001` 架构决策 + `docs/eval/` 评测结论整合而成，供本地确认后再发布到 GitHub Issue 跟踪器。
> UI 模式：**headless**（无可视化 UI，复用 WisCode 会话形态），省略 UI 章节、状态策略、页面清单。
> 评测单一事实源：`docs/eval/README.md`（判定规则预注册）+ `docs/eval/results.md`（两轮跑批实跑结果）。

## 问题陈述

现场用本脑「解析规则 → 添加字段」时，同事要写 **OGNL 表达式**（`<% %>`）、**Painless 表达式**（`{% %}`）或**字段引用**（`%{ }`）来从日志里抽/算字段。痛点是：

- 三种语法边界（`<% %>` / `{% %}` / `%{ }`）容易混淆，贴进平台跑不通还要回来猜；
- OGNL 的小众语义（投影 `.{? #this.x}`、`#`/`@` 静态调用）和 Painless 的 `def` 动态类型，凭记忆写错率高；
- 现场没人能手把手给「这个意图该用哪种语法、怎么写」，只能翻 FAQ 文档，但 FAQ 不会针对你这段日志给出可粘贴式子。

用户要的不是一份语法手册，而是「贴日志 + 说意图 + 期望效果 → 拿到能直接粘进平台跑通的表达式」，跑不通还能把报错原文贴回来迭代。

## 解决方案

做一个 WisCode skill（会话模式，非独立后端，见 ADR-0001）：复用 WisCode 运行时的 provider、文件系统与主对话模型，skill 只做四件事——约束输入三元组格式、注入知识库、规范输出形态、定义诊断式修正循环。

生产形态由评测结论锁定为「**薄契约 + FAQ 例子 KB 注入 + 按档路由模型（身份不可得时默认读 KB）**」：

- **薄契约**：SKILL.md 永久加载三种语法边界契约（逐字同 `docs/eval/README.md`「跑批注入上下文」换皮薄契约），不含具体写法示例；
- **FAQ 例子 KB 注入**：SKILL.md 永久加载从《OGNL常用写法FAQ》提炼的例子 KB，弱模型按需读取拉过线（第二条件实测：薄契约直出三档均 < 11/13，补 FAQ 例子后 地板 11/13、中档 11/13、天花板 13/13）；
- **按档路由（可观测时优化、不可观测时默认 KB）**：SKILL.md 静态文件读不到当前 model，但执行 skill 的 LLM 读得到自己的 model 身份——SKILL.md 写一条路由指令：身份可信且命中弱档清单 → 按需读 KB；身份不可得/不可验证（当前 WISCODE `Auto` 自动选模不暴露元数据）→ **默认读 KB**；身份可信且不在弱档清单 → 直出。路由靠 LLM 自读身份执行，**身份未知时不使用模型自报身份做归因**；
- **诊断式对话兜底**：首答不必满分，跑不通时用户贴回报错原文/实际输出值，skill 给 1–2 个修正方向的新表达式，工具不自动重试。

## 用户故事

US-1：作为现场运维/分析同事，我想要贴一段样例日志 + 用自然语言说我想抽/算什么 + 给出期望效果，以便拿到 1–2 个可直接粘贴进「添加字段」的表达式。

US-2：作为同事，我想要工具严格遵守三种语法边界（`<% %>` / `{% %}` / `%{ }`），以便生成的式子能直接粘进平台、不会因为边界符混淆跑不通。

US-3：作为同事，当表达式在现场没跑通时，我想要把本脑报错原文或实际输出值贴回来，以便工具据此给出 1–2 个修正方向的新表达式，我再拿去现场试，而不是工具替我自动重试。

US-4：作为同事，我想要工具默认按 OGNL / Painless 任选最合适的语言，而不是被强制用某一种，以便贴合现场本脑对该字段的能力支持。

US-5：作为弱模型用户（如地板档模型），我想要工具在我这条对话里自动加载 FAQ 例子 KB，以便我也能一发写出正确表达式，而不是只有强模型能用。

US-6：作为强模型用户，我想要工具在我这条对话里直出、不强制读 KB，以便节省 token、保持速度，因为我直出已能过线。

US-7：作为同事，我想要工具尊重现场本脑的白名单（静态类仅限白名单内），以便生成的式子不会因为我调用了白名单外的类（如 `java.net.URLDecoder`）而被平台拒绝。

US-8：作为同事，我想要工具主动考虑边界情况（空值、特殊字符），以便生成的式子在空值/异常输入下不报错、给出防御写法或说明限制。

US-9：作为经手人，我想要现场验证跑通的表达式自动存入 `docs/favorites/`，以便团队复用、跟随仓库 git 管理，且不与 Q&A 文档混为一谈。

US-10：作为 skill 维护者，我想要改 prompt / 加案例就是改 skill 文件，以便无需重新部署一个独立服务。

## 实现决策

### skill 形态：WisCode 会话模式

采用 WisCode skill（会话模式），不建独立后端服务。skill 复用 WisCode 运行时 provider、文件系统、主对话模型；生成阶段由主对话模型完成，skill 约束输入格式、注入 KB、规范输出、定义诊断循环。详见 ADR-0001。理由：诊断式对话天然是会话流；同事装 skill 即用，API Key 走每人自己的 WisCode provider，不耗单人额度、不需统一密钥运维；收藏落 `docs/favorites/` 跟随仓库可 git 管理。

### 输入三元组约束

skill 入口要求用户给齐三元组：`样例日志` + `意图` + `期望效果`。`期望效果` 须写成「应新增字段 xxx，值应为 yyy」的可逐字判等形式。三元组缺一不可——`期望效果` 是后续判等与诊断收敛的锚点，缺了它工具无法判「跑通」。

### 薄契约注入

SKILL.md 永久加载三种语法边界契约，逐字同 `docs/eval/README.md`「跑批注入上下文 · 换皮 17 条 · 纯语法薄契约」：声明 `<% %>` / `{% %}` / `%{ }` 三种语法与「前后不能/可拼接字符串」的约束、要求输出 1–2 个可直接粘贴的表达式、按出现顺序第 1 个表达式块为首选。契约不含任何 FAQ 写法示例（示例归 KB）。

### FAQ 例子 KB 注入

SKILL.md 永久加载 FAQ 例子 KB（从 `docs/reference/OGNL常用写法FAQ.md` 提炼）。KB 与薄契约分离：薄契约是跨题通用语法边界，KB 是按写法分类的例子。是否读 KB 由「按档路由指令」段决定：弱档/身份未知 model 按需读 KB，强档 model（身份可信且不在弱档清单内）直出不读。

### 按档路由指令

SKILL.md 写一条路由指令：LLM 自读 model 身份，若属于弱档清单则按需读 KB 例子再生成，否则直出。弱档 model 清单由第二条件跑批结果定（当前地板 `360-deepseek-v4-flash`、中档 `360-glm-5.2` 归弱档需读 KB，天花板 `claude-opus-4-8` 直出）。路由靠 LLM 自读身份执行，不靠 skill 框架切模型——因为 SKILL.md 静态文件读不到当前 model。

**身份不可得兜底（现实约束）**：当前 WISCODE 运行时不暴露可信 model 元数据（`Auto` 自动选模、不让自己选模型）。当执行 skill 的 LLM 无法可靠获得自身 model 身份时，无法证明当前模型是强档，故**默认读取相关 FAQ KB 再生成**——不读 KB 直出可能退回薄契约直出档（历史三档均 <11/13）。同时 `KB loaded` 只能记 `requested`/`unknown`，不得伪称已确认读取；历史三档数据只作离线基线，不作当前 Auto 的模型归因证据。

### 诊断式修正循环

skill 定义诊断循环：用户贴回报错原文或实际输出值 → skill 给 1–2 个修正方向的新表达式 → 用户再拿去现场试。**工具不自动重试、不替用户猜测报错**——必须由用户贴回真实反馈再迭代。这与 CONTEXT「边界与非目标」一致。

### 白名单兜底（契约侧）

edge 档白名单明文写入 SKILL.md 契约（静态类仅限 `com.alibaba.fastjson.JSON`、`org.apache.commons.lang3`、`com.hansight.dataviewer.utils`、`java.lang.Integer`），照抄 `docs/reference/lang-ref.md` 的 `ognl.whiteList`。评测结论：白名单守卫方向性信号弱（仅天花板 edge-01 1/3 硬编、地板/中档已守），暂不强制内置生成后守卫；edge-01 类白名单外类靠契约侧白名单提示兜底。

### 收藏落盘

经现场验证跑通的表达式条目自动存入 `docs/favorites/`，跟随仓库可 git 管理。收藏 ≠ Q&A：跑通只进收藏，Q&A 追加交给后续带标准的 skill 完成（见 CONTEXT 边界）。

## 测试决策

### 平台实跑判分 seam / 首选制逐字判等

判分锚点 = 现场平台实跑：表达式贴进本脑「添加字段」真跑，平台显示值即真值（不报错=有值，报错/空值=错）。不用任何模型模拟算值。一条 case = 一个判分点 = 只认首选表达式（模型输出里按出现顺序的第 1 个表达式块，前言说明不计入首选）。详见 `docs/eval/README.md`「判分标准」「多表达式判分口径」。

### 软硬分离硬门 seam / 类型盲区

17 条换皮题中 13 条类型敏感题进 80% 硬门分子（判对 ≥ 11/13 过线），4 条类型盲题（faq-01/04/05、qa-01）只记软过线、不进分子；盲区值错（值错 + 空值）≥ 2 触发结论降级，报错单列不计入降级。平台对标量（Number/String/Boolean）类型盲显示，标量题只判值、不卡类型，类型盲区进结论标注。

### L3 递归/正则/类型陷阱 seam / 重点回归

L3（faq-08/11/12、qa-04）作重点回归档。评测结论：第二条件 FAQ 例子注入后 L3 不再集体崩（天花板 L3 全过，地板/中档 L3 仅 faq-11 错），但 faq-11 域名去重类仍是最易漏去重的点，作 skill 回归必测项。

### edge 白名单硬编 seam / 硬编率独立计数

edge 3 条独立计硬编率：贴平台报错跑不通即判错、计入硬编率；正确识别「白名单外类不可行」或给出不依赖限制项的替代写法算对。当前硬编率方向性信号弱、暂不强制上守卫，沿用契约侧白名单兜底。

## 范围外

- **不做表达式自动重试**：工具不替用户猜测报错，必须由用户贴回真实反馈再迭代（CONTEXT 边界）。
- **不自动写入 Q&A 文档**：跑通只进 `docs/favorites/`；Q&A 追加交给后续带标准的 skill 完成。
- **不在本工具内做版本能力数据库**：3.5 与高版本的能力差异由用户在对话中说明，工具不维护版本矩阵。
- **不做独立后端服务**：当前目标用户都在 WisCode 环境内，不满足「不装 WisCode 的人也要用」的前提（ADR-0001）。
- **不做生成后白名单守卫的强制内置**：方向性信号弱，暂靠契约侧白名单提示兜底，留待 edge 跑批累计硬编共性后再裁决。
- **不补第二模型交叉验证**：第二条件三档硬门均过线，已支持「按档路由」结论，无需再补 Gemini/GPT 交叉验证。
