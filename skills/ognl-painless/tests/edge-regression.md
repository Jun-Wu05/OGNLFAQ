# Edge 白名单与边界回归集

> Issue #22。**skill 改动后必跑**。
> 来源与输入 SSOT：`docs/eval/edge-cases.md`。
> 判分 SSOT：`docs/eval/README.md`「判分标准 · 限制项」「edge 硬编率」。
> 这不是普通换皮题：正确识别限制项并说明不可行，或给出不依赖限制项的替代方向，算对；硬编一个平台跑不通的式子，算错并计入硬编率。

## 运行规则

1. 每个 case 新开对话，给完整输入三元组。
2. 首选表达式或首选限制项说明参与判定；备选仅作观察。
3. 记录“是否守白名单”和“是否主动自查边界”两个维度；不要把替代式的兼容性失败误记成硬编。

## 必测用例

### edge-01：白名单外 URLDecoder

- **case id**：`edge-01`
- **样例日志**：`{"req_path":"%2Fapi%2Fv1%2Flogin%3Fid%3D1"}`
- **意图**：req_path 是 URL 编码的，想解码成明文路径 `/api/v1/login?id=1`。
- **期望效果**：应正确指出当前版本 `URLDecoder` 未配置进白名单、OGNL 无法直接做 URL 解码，说明此路不通或给出不依赖白名单外类的替代方向。
- **正确应对**：明确 `java.net.URLDecoder` 不在白名单，不能输出 `@java.net.URLDecoder@decode(...)`；说明不可行或给不依赖白名单外类的替代方向。
- **硬编判错**：首选直接调用 `@java.net.URLDecoder@decode(req_path,"UTF-8")` 或其它白名单外静态类。
- **验证维度**：守白名单。

### edge-02：含换行 payload 的非空判断

- **case id**：`edge-02`
- **样例日志**：`{"payload":"line1\nline2"}`
- **意图**：在解析规则里对 payload 做非空判断（该字段值可能含换行符）。
- **期望效果**：应指出含换行的值用 `.+` 做整体匹配会失效（漏判），改用 `!= ""` 之类判断非空才可靠。
- **正确应对**：识别换行输入边界，给非空判断或等效防御方向。
- **硬编判错**：首选仍用 `.+` 做整体非空匹配，未说明换行场景。
- **验证维度**：主动自查特殊字符边界。

### edge-03：空 original_log 防御

- **case id**：`edge-03`
- **样例日志**：`{"original_log":""}`
- **意图**：原始日志有时为空字符串，为空时直接解析会报错，需要一种方式识别/处理空日志避免整条数据解析报错。
- **期望效果**：应给出空值防御思路（如为空时拼接标记前缀以便后续识别删除，或先判空再解析），而不是对可能为空的值裸取裸解析。
- **正确应对**：先判空或返回标记，再决定是否解析；说明空输入限制。
- **硬编判错**：对 `original_log` 直接调用解析/方法而没有任何空值防御。
- **验证维度**：主动自查空值边界。

## 汇总口径

- `硬编率 = 硬编条数 / 3`，三档独立记录。
- `> 30%` 仅是方向性信号（3 条中 ≥1 条）；是否上生成后白名单守卫，还要看硬编的是哪条、是否三档共性。
- 已守白名单或已有防御、但替代式因平台兼容性跑不通：判交付错，但**不计硬编**。
