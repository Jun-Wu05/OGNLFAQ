## 输入三元组约束（Issue #12 · SSOT：PRD「实现决策 › 输入三元组约束」）

skill 入口要求用户给齐三元组：`样例日志` + `意图` + `期望效果`。

- **样例日志**：一段真实/拟造日志原文，作为表达式生成与验证的输入。
- **意图**：自然语言描述「想对样例日志做什么」。
- **期望效果**：须写成「应新增字段 xxx，值应为 yyy」的可逐字判等形式。`期望效果` 是后续判等与诊断收敛的锚点，缺了它工具无法判「跑通」。

**校验规则：**

- 三元组缺 `样例日志` / `意图` / `期望效果` 任一 → **引导用户补齐，不进入生成**。给出缺哪一项、怎么补的提示，不要凭空编造输入。
- `期望效果` 非「应新增字段 xxx，值应为 yyy」形式 → **提示用户改写**到该形式再生成。例如「我想提取邮箱」不是合法 `期望效果`，应改写为「应新增字段 email，值应为提取到的邮箱地址」。
- 三元组齐备且 `期望效果` 合法后，才进入薄契约生成阶段。

## 薄契约注入：三种语法边界（Issue #10 · SSOT：PRD「实现决策 › 薄契约注入」+ `docs/eval/README.md`「跑批注入上下文 · 换皮 17 条 · 纯语法薄契约」）

> 本段是跨题通用的语法边界契约，**逐字同 `docs/eval/README.md`「跑批注入上下文 · 换皮 17 条 · 纯语法薄契约」**，不含任何 FAQ 写法示例（示例归 KB，见 `kb/faq-examples.md`）。

你在为一套解析规则「添加字段」生成表达式。可用三种语法：
- <% … %>  OGNL 表达式，返回任意 Java 对象，前后不能拼接字符串
- {% … %}  Painless 表达式，类 Java/Groovy，前后不能拼接字符串
- %{ … }   最基本字段引用，前后可拼接字符串
针对下面的样例日志与意图，输出 1–2 个可直接粘贴的表达式（`<% %>` / `{% %}` / `%{ }` 三种之一），按出现顺序的第 1 个表达式块即为你最推荐的首选，它前面可写自然语言说明（说明不计入首选）。

**契约要点（与上面薄契约同源，供执行时对照）：**

- 三种语法定义与「前后不能/可拼接字符串」约束是边界正确性的硬要求，混淆边界符贴进平台必报错。
- 「输出 1–2 个可直接粘贴的表达式」是交付形态要求——裸串（缺边界符）跑不通，等同交付失败。
- 「按出现顺序的第 1 个表达式块为首选」是判分锚点（首选制逐字判等）：模型常先写一段说明再给式子，前言说明不计入首选，取整条输出里第 1 个 `<% %>` / `{% %>` / `%{ }` 表达式块。
- 默认按 OGNL / Painless 任选最合适的语言，不强制用某一种，贴合现场本脑对该字段的能力支持。

## 按档路由指令（Issue #13 · SSOT：PRD「实现决策 › 按档路由指令」+ PRD「风险」）

**路由指令（LLM 自读身份执行）：** SKILL.md 是静态文件，读不到当前 model；但**执行 skill 的 LLM 读得到自己的 model 身份**。故路由靠 LLM 自读身份对照下方弱档清单执行，**不靠 skill 框架切模型**：

- 若你是**弱档 model**（你的 model 身份命中下方弱档清单）→ 生成前**按需读取** `kb/faq-examples.md` 中与用户意图相关的写法条目，再生成表达式。
- 否则（**强档 model**，不在弱档清单内）→ **直出**，不强制读 KB，以节省 token、保持速度。

> 评测依据：第二条件跑批（薄契约 + FAQ 例子）三档硬门均 ≥ 11/13——地板/中档靠读 KB 拉过线，天花板直出已 13/13。故弱档读 KB、强档直出，两条线都过线。详见 `docs/eval/results.md`。

## 诊断式修正循环（Issue #17 · SSOT：PRD「实现决策 › 诊断式修正循环」+ `CONTEXT.md`「边界与非目标」）

表达式首答不必满分。用户贴回**本脑报错原文**或**实际输出值**后，skill 据此给 **1–2 个修正方向**的新表达式，用户再拿去现场试。

**循环规则：**

- **工具不自动重试、不替用户猜测报错**——必须由用户贴回真实反馈再迭代（CONTEXT「边界与非目标」：不做表达式自动重试）。
- 修正方向须对照输入三元组的「期望效果」锚点（#12），给出**与首答不同方向**的写法（换语法 / 换写法 / 加防御），而非同义改写。
- 一次贴回 = 一轮迭代，每轮仍输出 1–2 个可粘贴表达式、第 1 个为首选；迭代直到首选平台实跑显示值与「期望效果」逐字判等。

## 白名单契约侧兜底（Issue #18 · SSOT：PRD「实现决策 › 白名单兜底（契约侧）」+ `docs/reference/lang-ref.md` `ognl.whiteList`）

可用静态类以白名单限制，**照抄 `docs/reference/lang-ref.md` 的 `ognl.whiteList`，不得自编**，仅含：

- `com.alibaba.fastjson.JSON`
- `org.apache.commons.lang3`
- `com.hansight.dataviewer.utils`
- `java.lang.Integer`

**未列出的类（如 `java.net.URLDecoder`）不可调用**——生成的式子若依赖白名单外类，贴平台会报错跑不通。遇到需白名单外类的意图时，给**不依赖限制项的替代写法**或**说明不可行**，不要硬编白名单外静态调用。

> 评测依据：白名单守卫方向性信号弱（仅天花板 edge-01 1/3 硬编、地板/中档已守白名单），暂不强制内置生成后守卫，靠本契约侧白名单提示兜底；留待 edge 跑批累计硬编共性后再裁决是否上生成后守卫（PRD「范围外」）。

## 空值/边界防御指引（Issue #19 · SSOT：`docs/eval/README.md`「跑批注入上下文 · 边界 3 条 · edge 附页」+ PRD「用户故事 US-8」）

生成表达式时**主动考虑输入边界（空值、特殊字符）**，必要时说明限制或给防御写法，避免表达式在空值/异常输入下报错。

- 空值场景给防御写法方向：判空（`#this != null` / `trim().equals("")`）、安全导航（`?.` 避免空指针）、为空返标记值。
- **不剧透具体坑**：只给边界自检方向（「自行考虑空值、特殊字符」），不提具体结论（如不直接说「`.+` 遇换行会漏」「空值会报错」），保留模型主动自查的空间。
- 与 #18 白名单区分：白名单管「类是否可调」，本段管「输入空值/特殊字符」。
